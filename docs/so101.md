# SO-101 real-arm runbook

The [SO-101](https://github.com/TheRobotStudio/SO-ARM100) follower driven by the same
interpreter as the Workshop sim ([simulators.md](simulators.md#so-101-isaac-lab-workshop)):
`interpreters/so101_atomic_controller.py` decides every motion; `core/so101/` only adds the
LeRobot I/O. What is verified in sim is what runs on the arm.

```
SO101Follower (LeRobot) -> ExactScale (angle correction) -> SafeArm (command limits)
  -> So101RealBackend (So101ArmController) -> So101AtomicExec (tokens)
```

| Path | What |
| --- | --- |
| `core/so101/units.py` | Workshop radians <-> LeRobot values (the Workshop's own mapping) |
| `core/so101/lerobot_io.py` | connect, motor overrides, read retries, `ExactScale`, `SafeArm`, `MockFollower` |
| `core/so101/real_backend.py` | `So101RealBackend` and the real-arm thresholds (`REAL_EXEC_KW`, `REAL_BACKEND_KW`) |
| `core/so101/cameras.py` | OpenCV cameras (newest frame from a background thread), video files for mock runs |
| `core/so101/rig.py` | builds the whole stack from `configs/robot_so101_real.yaml` |
| `scripts/so101/calibrate.py` | `lerobot-calibrate` for the lite install |
| `scripts/so101/tune_start.py` | match the start pose to the sim by eye, save per-joint zero offsets |
| `scripts/so101/verify_motion_real.py` | hardware counterpart of the sim's `verify_motion.py` |
| `tests/test_so101_real_io.py` | the above without hardware |

There is no VLM runner for the SO-101 yet (sim or real); this is the hardware layer a runner
would drive, the follow-up announced in the sim PR.

## 1. One-time setup (the PC the arm is plugged into)

```bash
python -m venv .venv
.venv/bin/pip install --no-deps lerobot==0.4.1
.venv/bin/pip install -r requirements/requirements-so101.txt
```

No torch is needed. On Windows set `PYTHONUTF8=1` in the shell first.

**Calibrate** (same arguments as `lerobot-calibrate`):

```bash
python scripts/so101/calibrate.py --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=follower_arm_1
```

- If a calibration file for that id exists, the first prompt reuses it unless you type
  `c` + Enter.
- Put every joint at the MIDDLE of its range before the first Enter. A joint that crosses the
  encoder wrap during the sweep records 0..4095; check the json and redo it if so.

## 2. Make the real arm match the sim

These are the differences that stopped the arm or made it miss, in the order they mattered.

1. **Angle scale.** LeRobot normalises each joint over the range swept during calibration, and
   the Workshop mapping assumes fixed degree ranges. One arm's sweep covered 227 deg of
   wrist_roll against the assumed 320 deg, which put the start pose 27 deg off.
   `robot.exact_scale: true` re-derives angles from encoder ticks (`ExactScale`).
2. **Joint zeros.** What remains depends on how symmetric the sweep was. Run
   `scripts/so101/tune_start.py --ref_dir <sim renders of the start pose>` and set
   `robot.joint_offset` to the saved file.
   - Mount the cameras as in the sim first.
   - Trust the front overlay over the wrist one: on a differently mounted wrist camera the
     wrist overlay pulled wrist_flex 13 deg toward its limit.
3. **Wrist camera orientation.** The fingertips must be at the BOTTOM of its raw image, as on
   the Workshop's ego camera.
4. **Mat height.** The Workshop's mat top is 3.5 cm above the robot base origin
   (`table_top_task_z_m`). With the base and the mat on the same table the hand closed 3.5 cm
   above the vials; raise the mat (and objects) to match.
5. **Objects.** Empty vials rolled away from the fingers; weighted ones stayed put.

## 3. Verify on hardware

Clear the table, keep a hand on the power, then:

```bash
python scripts/so101/verify_motion_real.py --port /dev/ttyACM0 --out runs/verify_real
python scripts/so101/verify_motion_real.py --mock --out /tmp/verify_mock   # no hardware
```

- Distances come from FK on the measured joints, so this checks the control (the hand goes
  where the interpreter says), not the absolute calibration.
- The criteria are in the script and were fixed before running. They are looser than the
  sim's because of sag and the low P gain.
- Task-run measurements so far are in [Measured](#measured).

## Settings and why

**Thresholds** (`core/so101/real_backend.py`). The sim values stopped the real arm on nearly
every token.

| Check | Sim | Real | Why |
| --- | --- | --- | --- |
| Arrived (position / orientation) | 1 mm / 0.2 deg | 4 mm / 1 deg | gravity sag and P=16 leave it a few mm short |
| At rest (per control step) | 0.3 mm / 0.05 deg | 1 mm / 0.3 deg | one encoder tick (0.088 deg) moves the fingertip ~0.4 mm |
| Contact (joint gap) | 0.08 rad | 0.15 rad | 0.087 rad was reached with the hand 11 cm above the mat |
| Joint-limit margin | 0.02 rad | 0.10 rad | the servos stop tracking ~5 deg before a limit |

**Motors** (`robot.strong_grip`, `robot.stiff_arm`). LeRobot's `configure()` sets every motor to
P=16 and the gripper to 50 % torque, 50 % current and 25 % torque on overload.

- **Grip:** a grasp that stalls on a vial counts as an overload, so the grip dropped to 25 %
  and held vials slipped.
- **Arm:** at P=16 the arm sagged ~1 cm holding a weighted vial with the shoulder back and the
  elbow folded.
- `strong_grip` sets the gripper to P 32 with 70 % / 70 % / 50 %. `stiff_arm` sets the arm
  joints to P 32. `verify_motion_real.py` reports the gripper temperature; let it cool above
  ~55 C.

**Safety.**
- `SafeArm` clips every command to the joint ranges and to `max_step_rad` (0.08 rad) per joint
  per command; LeRobot's `max_relative_target` stacks on top.
- The interpreter refuses any token whose end point leaves the workspace, comes within
  `min_joint_margin_rad` of a joint limit, or puts the hand hulls below
  `table_top + hand_floor_above_table_m`.
- Exiting a script leaves the arm limp (LeRobot disables torque on disconnect): support it.

## Measured

From the token logs of 9 real-arm episodes on the vials -> rack task (2026-10-24..26). Settings: `exact_scale` with a
`tune_start.py` offset, `strong_grip`, `stiff_arm`, the thresholds above. Those runs used an earlier
copy of `So101AtomicExec` that differs from this one only by renames and refactoring; MV_* and
RT_PITCH compute the same. Distances use FK on the joints measured before a token and before the next
decision, so they check the control, not the absolute calibration. These are task motions, not
the `verify_motion_real.py` protocol, so there is no out-and-back closure number.

| | Result | `verify_motion_real.py` criterion |
| --- | --- | --- |
| MV_* tokens | 207 executed, 195 completed, 12 stopped by the contact check | |
| Travel per token | median 20.4 mm, range 16.1-25.6, **188/195** within 16-24 | 16-24 mm |
| Off-axis | median 1.4 mm, **192/195** within 4 mm | <= 4 mm |
| Pitch change during a translation | max 1.8 deg | <= 3 deg |
| ... while holding a weighted vial | 77 tokens: median travel 20.4 mm, off-axis 1.6 mm | |
| RT_PITCH (one token) | **34/34** within 8-12 deg (8.6-11.2), TCP drift max 3.0 mm | 8-12 deg, <= 5 mm |

Per direction (completed tokens, travel mm): MV_FWD 17 (16.1-23.9), MV_BACK 15 (16.5-24.1),
MV_LEFT 6 (18.5-21.1), MV_RIGHT 66 (16.7-23.9), MV_UP 39 (16.7-25.2), MV_DOWN 52 (16.4-25.6).
